# 掌柜智库：当前版本全项目总思路链

> 这份图以当前工作区代码为准。阅读方法：从入口沿 `↓` 往下看，在出现 `├──` / `└──` 时看分支，在汇合处看多个结果如何重新进入下一个节点。
>
> 当前版本的关键事实：普通文档、Obsidian 笔记和教育资料最终都进入统一的 Milvus 集合 `knowledge_chunks_graph`；普通文档和 Obsidian 导入成功后还会构建 Neo4j 图；查询侧同时支持普通向量、Graph RAG、可选 HyDE 和可选 Web 检索。

## 0. 当前版本基准

```text
项目启动
  ↓
FastAPI 一体化服务
  ↓
app_service.py 注册查询、上传、导入、删除、会话、教育资料和静态前端路由
  ↓
所有后台任务使用 task_id 跟踪
  ↓
所有用户问答使用 session_id + message_id 关联 MongoDB 历史
  ↓
普通文档和 Obsidian 文档使用 ImportGraph
  ↓
教育资料使用 education_service 确定性解析链
  ↓
正文向量统一写入 Milvus：knowledge_chunks_graph
  ↓
图谱数据按 document_id 写入 Neo4j
  ↓
用户查询从 MongoDB 取上下文，从 Milvus / Neo4j / 可选 Web 召回
  ↓
RRF + Rerank + LLM
  ↓
SSE 推送进度、引用上下文、答案增量和最终结果
```

当前不是旧版的关系：

```text
旧版：普通向量 + HyDE → RRF
当前：普通向量 + Graph RAG + 可选 HyDE → RRF
      Web 结果保留在 State，并由 node_rerank 消费
```

## 2. FastAPI 服务总入口

```text
客户端打开前端
  ↓
GET /
  ↓
app_service.py 返回静态前端 index.html
  ↓
前端根据用户动作调用接口
  ├── 会话：GET /sessions、POST /sessions、PATCH /sessions/{session_id}、DELETE /sessions/{session_id}
  ├── 历史：GET /history/{session_id}、DELETE /history/{session_id}
  ├── 查询：POST /query、POST /query/{task_id}/cancel、GET /stream/{task_id}
  ├── 导入：POST /upload、POST /upload_obsidian、POST /import_local
  ├── 教育：POST /education/import、GET /education/status/{task_id}、GET /education/courses、GET /education/questions
  ├── 删除：DELETE /knowledge/documents/{document_id}、DELETE /knowledge/sources/{source_type}、DELETE /knowledge/directories
  └── 状态：GET /status/{task_id}、GET /health
  ↓
FastAPI 校验参数、文件和来源字段
  ↓
生成 task_id（任务追踪用，不作为文档身份）
  ↓
创建 queue_dict / 任务状态记录
  ↓
后台线程或 BackgroundTasks 执行 Graph / Service
  ↓
前端通过 SSE 或轮询读取状态
  ↓
queued → processing → completed / failed / cancelled
```

查询任务状态：

```text
请求进入 → queued → processing
                     ├── 查询模型等待 → waiting_response → processing
                     ├── 用户取消 → cancelled
                     ├── 异常 → failed
                     └── 全部成功 → completed
```

## 3. 查询链总图

```text
POST /query
  ↓
校验 session_id 和用户问题
  ↓
创建 task_id、初始化查询队列
  ↓
保存当前 user 消息到 MongoDB
  ↓
拿到当前 message_id
  ↓
读取最近历史和会话摘要
  ↓
组装 QueryGraphState
  ↓
QueryGraphRunner.create_and_run
  ↓
node_item_name_confirm
  ↓
after_confirm_router
  ├── State.answer 已存在 → node_answer_output
  ├── query_type == chitchat → node_answer_output
  └── 正常问题 → after_confirm_router 返回并行节点列表
        ├── node_search_embedding ──────────────┐
        ├── node_graph_search ──────────────────┤
        ├── node_search_embedding_hyde（可选） ──┤
        └── node_web_search_mcp（可选） ────────┘
                         ↓ 等待并行分支汇合
                     node_rrf
                         ↓
                     node_rerank
                         ↓
                 node_answer_output
                                      ↓
                                  Graph END
                                      ↓
                         queue_dict → GET /stream/{task_id}
```

### 3.1 node_item_name_confirm

```text
用户问题 original_query
  ↓
校验 session_id 和问题不为空
  ↓
保存 user 消息到 MongoDB chat_history
  ↓
拿到当前 message_id
  ↓
读取最近 HISTORY_LIMIT 条历史
  ↓
按时间从旧到新排列
  ↓
拼接 history_content
  ↓
先判断是不是元问题
  ├── “我刚才问了什么” / “上一轮说了什么”
  ├── “我们之前聊了什么” / “之前那个问题”
  └── 其他同类回顾历史表达
        ↓
      命中元问题
        ↓
      不调用 LLM
        ↓
      query_type = chitchat
      item_names = []
      rewritten_query = original_query
        ↓
      只更新当前 message_id
        ↓
      返回 QueryGraphState → node_answer_output

未命中元问题
  ↓
调用 LLM 做结构化识别
  ↓
LLM 产生 query_type + item_names + rewritten_query
  ↓
规范化和校验模型结果
  ↓
query_type == chitchat？
  ├── 是 → 不检索 → node_answer_output
  └── 否 → 继续主体确认
```

主体确认分支：

```text
item_names 有值
  ↓
对主体名称做 BGE-M3 向量化
  ↓
查询 Milvus item_collection
  ↓
只保留 score >= 0.5 的候选
  ↓
去重并保持模型原始顺序
  ↓
得到 final_item_names
  ↓
回写当前 message_id 的 item_names / rewritten_query / query_type
  ↓
返回 State

item_names 为空
  ↓
final_item_names = []
  ↓
不增加主体过滤
  ↓
后续允许宽泛检索

item_names 有值但匹配失败
  ↓
清空 item_names
  ↓
不阻断本轮查询
  ↓
退化为全库向量检索
```

节点边界：

```text
负责：消息落库、历史读取、元问题判断、意图识别、主体匹配、问题重写
不负责：正文召回、RRF、重排、最终答案生成
输出：query_type、item_names、rewritten_query、message_id、history
```

### 3.2 正常问题的召回分支

```text
正常问题
  ↓
after_confirm_router 返回并行节点列表
  ├── node_search_embedding（固定调度）
  │     ↓ embedding_chunks
  ├── node_graph_search（固定调度）
  │     ↓ graph_chunks + graph_paths
  ├── ENABLE_HYDE=true → node_search_embedding_hyde
  │     ↓ hyde_embedding_chunks
  └── ENABLE_WEB_SEARCH=true → node_web_search_mcp
        ↓ web_search_docs
  ↓
LangGraph 等待所有本轮已调度分支完成
  ↓
汇合到 node_rrf
```

## 4. 普通向量检索：node_search_embedding

```text
node_search_embedding
  ↓
读取 rewritten_query、query_type、item_names
  ↓
BGE-M3 生成 dense_vector + sparse_vector
  ↓
确定集合：knowledge_chunks_graph
  ↓
确定内容过滤
  ├── course → content_type == course_intro
  ├── question → content_type == question
  └── doc / knowledge → 不强制 content_type
  ↓
确定主体过滤
  ├── doc / knowledge 且 final_item_names 有值 → 增加 item_name 过滤
  ├── doc / knowledge 且没有主体 → 不加主体过滤，宽泛检索
  └── course / question → 不叠加 item_name 过滤，避免零召回
  ↓
Milvus dense + sparse 混合搜索
  ↓
每一路 limit = 20
  ↓
写入 embedding_chunks
  ↓
node_rrf
```

```text
带 item_name 过滤查询
  ↓
命中结果？
  ├── 是 → 返回主体过滤结果
  └── 否 → 去掉 item_name 过滤 → 全库混合检索 → embedding_chunks
```

## 5. HyDE 检索：node_search_embedding_hyde

```text
node_search_embedding_hyde
  ↓
读取 rewritten_query、query_type、item_names
  ↓
query_type == course？
  ├── 是 → hyde_embedding_chunks=[]，不调用 LLM，不检索
  └── 否 → 继续
  ↓
query_type == question？
  ├── 是 → hyde_embedding_chunks=[]，不调用 LLM，不检索
  └── 否 → 继续
  ↓
doc / knowledge
  ↓
调用 LLM 生成与问题相关的假设性答案
  ↓
拼接 rewritten_query + hyde_answer
  ↓
BGE-M3 生成 dense + sparse
  ↓
应用主体过滤策略
  ↓
主体过滤零命中？
  ├── 否 → 返回 hyde_embedding_chunks
  └── 是 → 去掉主体过滤重新检索 → hyde_embedding_chunks
  ↓
node_rrf
```

开关含义：

```text
ENABLE_HYDE=false → 普通文档只走 node_search_embedding
ENABLE_HYDE=true  → 普通文档增加 HyDE 召回
course/question   → 即使节点被调度，也在节点内部直接返回空列表
```

## 6. Graph RAG 查询：node_graph_search

```text
node_graph_search
  ↓
读取 item_names、query_type
  ↓
item_names 为空？
  ├── 是 → graph_chunks=[]、graph_paths=[]，不做无主体图遍历
  └── 否
        ↓
      query_type 映射 content_type
        ├── course → course_intro
        ├── question → question
        └── doc / knowledge → 不强制类型
        ↓
      GraphStore.find_related_chunks
        ↓
      以主体为起点，默认 hops = 2
        ↓
      Neo4j 返回 chunk_id + path
        ↓
      以 chunk_id 回 Milvus knowledge_chunks_graph 取完整正文和元数据
        ↓
      附加 source=graph、graph_path、score=0.0
        ↓
      graph_chunks + graph_paths
        ↓
      node_rrf
```

故障容错：

```text
Neo4j 连接或图查询失败
  ↓
记录 warning
  ↓
graph_chunks=[]、graph_paths=[]
  ↓
继续依靠普通向量 / HyDE / Web
  ↓
Graph 不是硬依赖
```

## 7. Web 检索与多路汇合

```text
正常问题
  ↓
ENABLE_WEB_SEARCH=true？
  ├── 否 → 不执行 node_web_search_mcp
  └── 是 → node_web_search_mcp → rewritten_query → web_search_docs
```

```text
embedding_chunks ───────┐
hyde_embedding_chunks ──┼──→ node_rrf → rrf_chunks ──┐
graph_chunks ───────────┘                             │
                                                     ├──→ node_rerank
web_search_docs ─────────────────────────────────────┘
```

```text
node_rrf 实际读取：embedding_chunks、hyde_embedding_chunks、graph_chunks
node_rrf 不把 web_search_docs 算进 RRF 分数
node_rerank 读取 rrf_chunks + web_search_docs，做统一重排和合并
```

## 8. RRF 与 Rerank

### 8.1 node_rrf

```text
embedding_chunks → 按 score 排 rank → 权重 1.0 ──┐
hyde_embedding_chunks → 按 score 排 rank → 权重 0.8 ─┼→ node_rrf
graph_chunks → 按返回顺序排 rank → 权重 1.5 ────┘
  ↓
按 chunk_id 聚合相同结果
  ↓
rrf_score += weight / (rrf_k + rank + 1)
  ↓
默认 rrf_k = 60
  ↓
合并并保留 graph_path 等图证据
  ↓
按 RRF 分数排序
  ↓
State.rrf_chunks
  ↓
node_rerank
```

### 8.2 node_rerank

```text
node_rerank
  ↓
读取 rrf_chunks + web_search_docs
  ↓
统一整理本地 Chunk 和 Web 文档
  ↓
调用重排模型 / 重排逻辑
  ↓
比较问题与候选证据相关性
  ↓
按重排分数排序
  ↓
State.reranked_docs
  ↓
node_answer_output
```

## 9. 答案生成与流式输出：node_answer_output

```text
node_answer_output
  ↓
State.answer 已存在？
  ├── 是 → 保存 assistant → put_data(final) → 结束本轮
  └── 否
        ↓
      读取 chat_summary
        ↓
      读取最近 QUERY_HISTORY_LIMIT 条原始历史
        ↓
      组合长期摘要 + 最近对话
        ↓
      判断 query_type 和 reranked_docs
```

答案分支：

```text
query_type == chitchat
  ↓
CHAT_PROMPT → 带历史调用 LLM → 流式 delta

reranked_docs 为空
  ↓
NO_RESULT_PROMPT
  ↓
说明知识库没有找到充分资料
  ↓
结合历史生成兜底回答 → 流式 delta

reranked_docs 有结果
  ↓
拼 title / source / url / content
  ↓
丢弃明显过低的候选
  ↓
只截过长 Chunk，不截当前问题
  ↓
fit_prompt_fields 控制检索资料、历史、问题和输出空间预算
  ↓
组装 ANSWER_PROMPT → llm.stream
```

```text
模型返回 delta
  ↓
put_data(task_id, delta, delta)
  ↓
前端 EventSource 收到增量
  ↓
累积完整 answer
  ↓
检查 finish_reason
  ├── 正常结束 → 图片、历史、final
  ├── length / max_tokens / token_limit
  │     ↓
  │   按 continuation 机制从末尾继续，不重复全文
  │     ↓
  │   完成后保存历史并 final
  └── 网络 / 模型异常
        ↓
      有部分内容 → 保留并追加可读错误收尾
      无内容 → 返回友好错误提示
```

```text
完整 answer
  ↓
提取召回 Chunk 图片引用
  ↓
完整 HTTP URL 直接保留；相对路径补成 MinIO URL
  ↓
图片 URL 去重
  ↓
保存 assistant 到 MongoDB
  ↓
final：answer + image_urls
  ↓
异步压缩较早历史到 chat_summary
```

## 11. Obsidian 上传导入链：POST /upload_obsidian

```text
用户拖拽 Vault 文件夹，或批量选择多个笔记
  ↓
前端 webkitGetAsEntry / webkitdirectory 递归读取
  ↓
保留相对 Vault 根目录的路径
  ↓

  ↓
POST /upload_obsidian
  ↓

  ↓

  ↓

  ↓
```

接口边界：


### 13.2 node_entry

```text

  ↓
识别后缀
  ↓
设置 is_md_read_enabled / is_pdf_read_enabled / is_docx_read_enabled
  ↓
设置 file_title
  ↓
保留 source_type / source_id / source_path / document_id
  ↓
没有 document_id → 根据来源三元组计算稳定 document_id
  ↓
.md → md_path → node_md_img
.pdf → pdf_path → node_pdf_to_md
.docx → docx_path → node_docx_to_md
其他后缀 → 失败
```

### 13.3 node_pdf_to_md

```text
pdf_path + local_dir
  ↓
上传 PDF 到解析服务
  ↓
拿 batch_id 和上传 URL
  ↓
按 URL 上传并确认
  ↓
轮询解析状态
  ↓
获得 Markdown zip 地址
  ↓
下载、解压并找到 Markdown
  ↓
读取 md_content + md_path
  ↓
node_md_img
```

上传、轮询、下载、解压任一环节失败 → 当前任务 failed。

### 13.4 node_docx_to_md

```text
检查 docx_path
  ↓
延迟导入 python-docx
  ├── 依赖不存在 → 提示安装 → failed
  └── 依赖存在 → Document(docx_path)
        ↓
      按 Word body 原顺序遍历
        ├── 段落 p → 读取文本 → Heading 1~4 转 #~#### → 普通段落原样加入
        └── 表格 tbl → 读取单元格 → 用 | 拼 Markdown 表格行
  ↓
两个换行拼成 md_content
  ↓
内容为空 → failed；有内容 → 写入 *_converted.md
  ↓
返回 md_path + md_content → node_md_img
```

当前主要提取段落、标题和表格，不把 DOCX 内嵌图片处理写成已完成能力。

### 13.5 node_md_img

```text
读取 md_path 或 State.md_content
  ↓
内容为空 → 失败；有内容 → 定位同级 images/
  ↓
识别 jpg / jpeg / png / gif / bmp / webp
  ↓
查找 Markdown ![描述](images/a.png) 或 HTML <img src="...">
  ↓
截取图片附近约 200 字符上下文
  ↓
视觉模型生成图片摘要
  ↓
限制并发；速率限制 / 网络失败使用指数退避重试
  ↓
上传图片到 MinIO
  ↓
原引用替换为图片摘要 + MinIO URL
  ↓
写入 *_backup.md
  ↓
输出处理后的 md_content → node_document_split
```

### 13.6 node_document_split

```text
优先使用 State.md_content，否则从 md_path 读取
  ↓
统一换行，按行拆分
  ↓
标题 # 到 ###### 建立树形章节
  ↓
标题栈维护层级；代码块内 # 不作为标题
  ↓
正文记录 breadcrumb / section_path，记录 parent_key
  ↓
无标题开头归入 file_title
  ↓
合并过小兄弟区块
  ├── 父路径相同
  ├── 正文短于 MERGE_MIN_BODY
  ├── 当前不是表格
  └── 前一个也不是表格
  ↓
RecursiveCharacterTextSplitter 精切
  ├── 不超过 CHUNK_SIZE → 整节保留
  ├── 小表格且不超过 MAX_WHOLE_SECTION → 尽量完整
  └── 超长正文 → 空行、换行、表格行、句号等递归切分
  ↓
CHUNK_OVERLAP 保留相邻语义
  ↓
chunks[]：chunk_id / document_id / chunk_index / section_path / content / file_title
  ↓
node_item_name_recognition
```

稳定 Chunk 身份：

```text
document_id + chunk_index + section_path + content
  ↓ SHA-256
chunk_id
  ↓
Milvus 和 Neo4j 用同一个 chunk_id 关联正文证据
```

### 13.7 node_item_name_recognition

```text
chunks + file_title
  ↓
构造不超过 12000 字符的 evidence
  ├── 文件名
  ├── 去重章节标题索引
  ├── 开头代表性 Chunk
  ├── 中间代表性 Chunk
  └── 结尾代表性 Chunk
  ↓
调用 LLM 识别主体名称
  ↓
规范化输出
  ├── 列表取第一个非空值
  ├── 多行取第一行非空内容
  ├── 去“主体名称：”前缀、引号、反引号、结尾标点
  ├── 拒绝“不确定 / 未知 / null / none”
  └── 名称不在 evidence → 回退 file_title
  ↓
确保 item_collection 存在
  ↓
主体名称向量化并校验非空
  ↓
转义 Milvus 过滤字符串
  ↓
删除 item_collection 同名旧主体
  ↓
插入新的主体名称和向量
  ↓
给每个 Chunk 写入 item_name
  ↓
State.item_name + State.chunks → node_bge_embedding
```

内部纯函数契约：

```text
build_item_name_evidence → 从元数据、标题、代表性 Chunk 构造有限证据
normalize_item_name → 清理不稳定模型输出，并拒绝证据中不存在的名称
escape_milvus_string → 转义引号和反斜杠，避免污染过滤表达式
```

### 13.8 node_bge_embedding

```text
带 item_name 的 chunks
  ↓
每 3 个 Chunk 一批
  ↓
拼接 file_title + item_name + content
  ↓
BGE-M3 批量生成 dense_vector + sparse_vector
  ↓
按原顺序写回 Chunk
  ↓
校验所有向量完成
  ↓
node_import_milvus
```

### 13.9 node_import_milvus

```text
带向量 chunks + 来源字段
  ↓
补齐 document_id、source_type、source_id、source_path、source_name、file_hash、file_title
  ↓
没有 document_id → build_document_id(source_type, source_id, source_path 或 file_title)
  ↓
校验字段、字符串长度、dense_vector、sparse_vector
  ├── 失败 → 旧 document_id 数据不删除 → 任务 failed
  └── 成功
        ↓
      KnowledgeChunkStore.replace_document
        ↓
      删除 Milvus 同 document_id 的旧 Chunks
        ↓
      插入新 Chunks
        ↓
      返回 document_id + 写入结果
        ↓
      node_graph_build
```

### 13.10 node_graph_build

```text
确认 Milvus 已成功写入当前 document_id
  ↓
读取当前文档 Chunks
  ↓
构造图谱抽取证据，大文档分批调用 LLM
  ↓
抽取实体和关系 JSON
  ↓
解析 JSON；失败 / 无效输出 → 重试
  ↓
规范化实体和别名，合并同类型同别名实体
  ↓
校验关系端点存在、关系类型在白名单
  ↓
保留关系证据 Chunk
  ↓
GraphStore.replace_document(document_id)
  ↓
删除当前文档旧图
  ↓
写入 Document / Chunk / Entity / Relation
  ↓
ImportGraph END
```

## 15. 文档身份、统一存储、覆盖和删除

稳定身份：

```text
source_type + source_id + source_path
  ↓ build_document_id
document_id
  ↓
同一身份再次导入 → replace_document → 找到并覆盖旧数据
```

来源身份：

```text
普通浏览器：source_type=document，source_id=browser-upload，source_path=文件名
Obsidian：source_type=obsidian，source_id=browser-upload:Vault名称，source_path=Vault 内相对路径
本地目录：source_type=document，source_id=目录绝对路径，source_path=目录内相对路径
教育资料：source_type=education，source_id=课程介绍或题目资料，source_path=课程介绍或题目资料
```

```text
task_id、临时目录和上传批次不参与 document_id 计算
同名文件不等于全局覆盖；三项来源身份完全一致才会覆盖
```

统一集合：

```text
KnowledgeChunkStore
  ↓
knowledge_chunks_graph
  ├── id / chunk_id / document_id
  ├── source_type / source_id / source_path
  ├── item_name / content_type
  ├── chunk_index / section_path / content
  └── dense_vector / sparse_vector
```

覆盖链：

```text
新 Chunk 完成向量化
  ↓
replace_document(document_id, new_chunks)
  ↓
先完整校验新数据
  ├── 失败 → 旧数据保留
  └── 成功 → 删除旧 Chunks → 插入新 Chunks → node_graph_build 替换旧图
```

删除链：

```text
DELETE /knowledge/documents/{document_id}
  ↓
删除 Milvus 当前 document_id Chunks
  ↓
删除 Neo4j 当前 document_id 图数据

DELETE /knowledge/sources/{source_type}?source_id=...
  ↓
按 source_type + source_id 找文档
  ↓
删除所有对应 Milvus Chunks
  ↓
逐个 document_id 删除 Neo4j 图

DELETE /knowledge/directories
  ↓
按 source_path 前缀找目录下文档
  ↓
删除 Milvus Chunks
  ↓
同步删除对应 Neo4j 图
```

```text
Neo4j 删除失败
  ↓ warning
  ↓ 不阻断已经成功的 Milvus 删除结果
```

## 21. 从一次导入到一次查询的闭环

```text
上传文档
  ↓
source_type + source_id + source_path → document_id
  ↓
node_entry → 格式转换 → 图片摘要和 URL 替换
  ↓
章节解析 → Chunk 切分 → 主体识别
  ↓
BGE-M3 dense + sparse
  ↓
Milvus 校验成功 → 删除同 document_id 旧 Chunk → 写入 knowledge_chunks_graph
  ↓
node_graph_build → 替换 Neo4j 当前文档图
  ↓
用户提问 → MongoDB message_id + 历史
  ↓
意图 / 主体 / 问题重写
  ↓
普通向量 + Graph + 可选 HyDE + 可选 Web
  ↓
RRF → Rerank → 上下文预算控制 → LLM 流式答案
  ↓
MongoDB 保存答案 + SSE 返回前端
```

这就是当前项目真正的总链路：导入负责把资料变成带稳定身份、向量和图关系的证据；查询负责选择检索分支、合并证据并生成答案；删除和覆盖始终围绕同一个 `document_id` 同步处理 Milvus 与 Neo4j。

掌柜智库：当前版本全项目总思路链

按当前代码整理的纯文本箭头链路：入口 → 节点 → 分支 → 汇合 → 存储 → 前端输出。重点展示 Graph RAG、HyDE、稳定 document_id、统一知识集合和删除链。

总图查询链节点详链导入链教育链图谱链存储删除答案输出节点索引

一张总图

所有资料导入统一进入 Milvus；普通文档和 Obsidian 成功写入后继续构建 Neo4j 图；查询侧组合普通向量、Graph、可选 HyDE 和可选 Web。

  ├── POST /import_local → 本地目录扫描后进入 ImportGraph
  ├── POST /education/import → 教育资料确定性解析链
  └── DELETE /knowledge/... → Milvus + Neo4j 联动删除

普通文档 / Obsidian / 本地目录
  ↓
node_entry → 格式转换 → node_md_img
  ↓
node_document_split → node_item_name_recognition
  ↓
node_bge_embedding → node_import_milvus
  ↓
knowledge_chunks_graph → node_graph_build → Neo4j

教育资料
  ↓

用户问题
  ↓
node_item_name_confirm → after_confirm_router
  ├── answer / chitchat → node_answer_output
  └── 正常问题 → after_confirm_router 返回并行节点列表
        ├── node_search_embedding ──────────────┐
        ├── node_graph_search ──────────────────┤
        ├── node_search_embedding_hyde（可选） ──┤

查询链

意图、主体和重写

用户问题 original_query
  ↓
保存 MongoDB chat_history → 拿 message_id
  ↓
读取最近 HISTORY_LIMIT 条历史 → 拼 history_content
  ↓
判断元问题
  ├── 是 → query_type=chitchat，item_names=[]，不调用 LLM
  │          ↓
  │        node_answer_output
  └── 否 → LLM 结构化识别
             ↓ query_type + item_names + rewritten_query
           query_type == chitchat？
             ├── 是 → node_answer_output
             └── 否 → 继续主体确认

item_names 有值 → BGE-M3 → Milvus item_collection
  ↓
保留 score >= 0.5 → 去重保序 → final_item_names
  ↓
只回写当前 message_id

item_names 为空或主体匹配失败
  ↓
final_item_names=[] → 不阻断查询 → 后续宽泛检索

多路召回和汇合

正常问题
  ↓
after_confirm_router 返回并行节点列表
  ├── node_search_embedding（必走）
  │     ↓ embedding_chunks
  ├── node_graph_search
  │     ├── 无主体 → graph_chunks=[]、graph_paths=[]
  │     └── 有主体 → Neo4j hops=2 → chunk_id → Milvus 正文
  │                            ↓ graph_chunks + graph_paths
  ├── ENABLE_HYDE=true → node_search_embedding_hyde
  │                         ↓ hyde_embedding_chunks
  └── ENABLE_WEB_SEARCH=true → node_web_search_mcp
                                ↓ web_search_docs
  ↓ 等待所有本轮已调度分支完成
embedding + graph + hyde → node_rrf → rrf_chunks
  ↓
rrf_chunks + web_search_docs → node_rerank → reranked_docs
  ↓
node_answer_output
准确关系：RRF 读取普通向量、Graph 和 HyDE；Web 结果保留在 State，交给 node_rerank 与 RRF 结果一起重排。

查询节点逐个展开

node_item_name_confirm：意图、主体与问题重写

original_query
  ↓
校验 session_id 和问题
  ↓
写入 MongoDB chat_history
  ↓
拿当前 message_id
  ↓
读取最近 HISTORY_LIMIT 条历史
  ↓
按时间从旧到新重排 → 拼 history_content
  ↓
判断“我刚才问了什么 / 上一轮说了什么”等元问题
  ├── 命中 → 不调用 LLM
  │          ↓ query_type=chitchat，item_names=[]，rewritten_query=original_query
  │          ↓ 只更新当前 message_id → node_answer_output
  └── 未命中 → 调用 LLM 结构化识别
             ↓ query_type + item_names + rewritten_query
           query_type=chitchat？是 → node_answer_output
                              否 → 继续主体匹配
  ↓
item_names 有值 → BGE-M3 → item_collection → score >= 0.5 → 去重保序
  ↓
final_item_names → 回写当前 message_id → 返回 QueryGraphState
  ↓
主体为空 / 匹配失败 → item_names=[] → 不阻断 → 后续宽泛检索

node_search_embedding：普通混合向量检索

rewritten_query + query_type + final_item_names
  ↓
BGE-M3 → dense_vector + sparse_vector
  ↓
查询 knowledge_chunks_graph
  ↓
course → content_type=course_intro
question → content_type=question
doc / knowledge → 不强制 content_type
  ↓
doc / knowledge 有主体 → 增加 item_name 过滤
doc / knowledge 无主体 → 宽泛检索
course / question → 不叠加 item_name 过滤
  ↓
Milvus dense + sparse 混合搜索，每路 limit=20
  ↓
有主体过滤且零命中？是 → 去掉 item_name 过滤 → 全库重试
  ↓
embedding_chunks → node_rrf

node_search_embedding_hyde：条件式第二路检索

读取 rewritten_query + query_type
  ↓
course / question？
  ├── 是 → hyde_embedding_chunks=[] → 不调 LLM → 不做第二次向量检索
  └── 否 → doc / knowledge
             ↓
           LLM 生成假设性答案
             ↓
           rewritten_query + hyde_answer
             ↓
           BGE-M3 → dense + sparse → Milvus
             ↓
           主体过滤零命中？是 → 去掉主体过滤 → 全库重试
             ↓
           hyde_embedding_chunks → node_rrf

node_graph_search：按关系扩展证据

item_names + query_type
  ↓
没有主体 → graph_chunks=[]、graph_paths=[] → node_rrf
  ↓
有主体 → query_type 映射 content_type
  ↓
GraphStore.find_related_chunks(hops=2)
  ↓
Neo4j 返回 chunk_id + path
  ↓
按 chunk_id 回 knowledge_chunks_graph 取完整正文
  ↓
附加 source=graph、graph_path、score=0.0
  ↓
graph_chunks + graph_paths → node_rrf

Neo4j 故障 → warning → 空图结果 → 继续其他召回

node_web_search_mcp：可选外部检索

ENABLE_WEB_SEARCH=true
  ↓
使用 rewritten_query 调用 Web MCP
  ↓
整理标题、正文、URL
  ↓
web_search_docs
  ↓
保留到 State，交给 node_rerank

ENABLE_WEB_SEARCH=false → 不注册 / 不执行 Web 节点

node_rrf：普通向量、HyDE、Graph 融合

embedding_chunks → rank → weight=1.0 ─────┐
hyde_embedding_chunks → rank → weight=0.8 ──┼→ node_rrf
graph_chunks → rank → weight=1.5 ──────────┘
  ↓
按 chunk_id 合并重复 Chunk，保留 graph_path
  ↓
rrf_score += weight / (rrf_k + rank + 1)
  ↓
默认 rrf_k=60 → 按分数排序
  ↓
rrf_chunks → node_rerank

注意：web_search_docs 不参与 RRF 分数计算

node_rerank：统一重排

rrf_chunks + web_search_docs
  ↓
统一整理本地 Chunk 和 Web 文档
  ↓
调用重排模型 / 重排逻辑
  ↓
比较问题与候选证据相关性
  ↓
按重排分数排序
  ↓
reranked_docs → node_answer_output

node_answer_output：答案、续接和前端输出

State.answer 已存在？
  ├── 是 → 保存 assistant → final → 结束
  └── 否 → chat_summary + 最近 QUERY_HISTORY_LIMIT 条历史
             ↓
           chitchat → CHAT_PROMPT → LLM
           无结果 → NO_RESULT_PROMPT → 兜底回答
           有结果 → title/source/url/content → 上下文预算 → ANSWER_PROMPT
             ↓
           llm.stream → 每个 delta 写入队列 → SSE
             ↓
           正常结束 → 收尾
           length / max_tokens → 从末尾续接，不重复全文
           网络 / 模型异常 → 保留已有内容并追加可读收尾
             ↓
           提取图片 URL → MongoDB 保存 assistant
             ↓
           final(answer + image_urls) → 异步更新 chat_summary

普通、Obsidian、本地导入链

普通上传 /upload
  ↓ 批量文件：主文档 + 附属图片
source_type=document / source_id=browser-upload / source_path=文件名
  ↓ 稳定 document_id → ImportGraph

Obsidian 上传 /upload_obsidian
  ↓ 浏览器拖拽 Vault / 文件夹，保留 Vault 相对路径
source_type=obsidian / source_id=browser-upload:Vault名称 / source_path=相对路径
  ↓ 每篇 Markdown 一个任务 → ImportGraph

本地扫描 /import_local
  ↓ 服务端读取目录及其文档
source_type=document / source_id=目录绝对路径 / source_path=目录内相对路径
  ↓ 每个文档 → ImportGraph

三种入口
  ↓
node_entry
  ├── .md → node_md_img
  ├── .pdf → node_pdf_to_md → node_md_img
  └── .docx → node_docx_to_md → node_md_img
  ↓
node_document_split → node_item_name_recognition
  ↓
node_bge_embedding → node_import_milvus → node_graph_build → END

通用导入节点逐个展开

node_entry
  ↓ 校验文件存在、读取后缀、设置读取标志和 file_title
  ↓ 保留 source_type / source_id / source_path
  ↓ 没有 document_id → 根据来源三元组计算稳定 document_id
  ↓ .md → node_md_img；.pdf → node_pdf_to_md；.docx → node_docx_to_md

node_pdf_to_md
  ↓ pdf_path → PDF 解析服务 → batch_id / 上传 URL
  ↓ 上传 PDF → 轮询解析 → 下载 Markdown zip → 解压
  ↓ 读取 md_content + md_path → node_md_img
  ↓ 任一服务环节失败 → 当前任务 failed

node_docx_to_md
  ↓ 校验路径 → 延迟导入 python-docx → Document(docx_path)
  ↓ 按 Word body 原顺序遍历
  ├── 段落 → Heading 1~4 转 #~####；普通段落原样保留
  └── 表格 → 逐行读取单元格 → Markdown 表格
  ↓ 两个换行拼 md_content → 写 *_converted.md → node_md_img
  ↓ 当前主要提取段落、标题、表格，不处理 DOCX 内嵌图片

node_md_img
  ↓ 读取 Markdown → 定位同级 images/
  ↓ 找 Markdown 图片或 HTML 图片引用
  ↓ 截取图片附近约 200 字符 → 视觉模型生成摘要
  ↓ 限制并发；速率 / 网络错误指数退避重试
  ↓ 上传 MinIO → 原引用替换为摘要 + URL
  ↓ 写 *_backup.md → 输出 md_content → node_document_split

node_document_split
  ↓ State.md_content 优先，否则读取 md_path
  ↓ 统一换行 → 标题栈建章节树 → breadcrumb / section_path
  ↓ 代码块内 # 不当标题；记录 parent_key
  ↓ 合并过小兄弟区块
  ↓ RecursiveCharacterTextSplitter 精切
  ↓ CHUNK_SIZE / MAX_WHOLE_SECTION / CHUNK_OVERLAP
  ↓ 输出 chunk_id、document_id、chunk_index、section_path、content

node_item_name_recognition
  ↓ 文件名 + 去重章节标题 + 开头/中间/结尾代表性 Chunk
  ↓ evidence 上限 12000 字符 → LLM 识别主体
  ↓ 清理前缀、引号、标点和 unknown/null 等不确定值
  ↓ 名称不在 evidence → 回退 file_title
  ↓ 主体向量化 → 删除 item_collection 同名旧主体 → 插入新主体
  ↓ 给每个 Chunk 写 item_name → node_bge_embedding

node_bge_embedding
  ↓ 每 3 个 Chunk 一批
  ↓ 拼 file_title + item_name + content
  ↓ BGE-M3 → dense_vector + sparse_vector
  ↓ 按原顺序写回并校验 → node_import_milvus

node_import_milvus
  ↓ 补齐来源元数据和 document_id
  ↓ 校验字段、长度、dense_vector、sparse_vector
  ├── 失败 → 旧数据不删除 → task failed
  └── 成功 → replace_document → 删除同 document_id 旧 Chunk → 插入新 Chunk
                                      ↓ node_graph_build

node_graph_build
  ↓ 确认 Milvus 写入成功 → 读取当前文档 Chunk
  ↓ 大文档分批 → LLM 抽实体 / 关系 JSON
  ↓ 解析 → 规范化别名 → 合并实体 → 校验端点和关系白名单
  ↓ GraphStore.replace_document(document_id)
  ↓ 删除旧图 → 写入 Document / Chunk / Entity / Relation → END

  └── content_type=question

  ↓

教育查询
  ↓
course → content_type=course_intro
question → content_type=question
  ↓
不叠加 item_name 过滤；HyDE 节点内部跳过

图谱链

导入时构建，查询时使用

Milvus 写入成功 → node_graph_build
  ↓
读取 document_id 的 Chunks → 大文档分批 → LLM 抽实体和关系 JSON
  ↓
解析 → 规范化别名 → 合并实体 → 校验端点和关系白名单
  ↓
GraphStore.replace_document(document_id)
  ↓ 删除旧图 → 写入 Document / Chunk / Entity / Relation → Neo4j

Document ──CONTAINS──→ Chunk ──MENTIONS──→ Entity
Chunk ──NEXT──→ Chunk
Entity ──业务关系──→ Entity

查询时：item_names → node_graph_search → Neo4j hops=2
  ↓
chunk_id + path → 回 Milvus knowledge_chunks_graph 取正文
  ↓
source=graph / graph_path / score=0.0
  ↓
graph_chunks → node_rrf

无主体或 Neo4j 故障 → graph 结果为空 → 继续向量 / HyDE / Web
Graph 是增强检索，不是硬依赖

存储、覆盖和删除

source_type + source_id + source_path
  ↓ build_document_id
document_id
  ↓
KnowledgeChunkStore.replace_document
  ↓
校验新 Chunk
  ├── 失败 → 旧数据保留 → 任务 failed
  └── 成功 → 删除旧 document_id → 插入新 Chunk
                         ↓
                       node_graph_build → 替换旧图

统一集合：knowledge_chunks_graph
  ↓ id / chunk_id / document_id / source_type / source_id / source_path
    item_name / content_type / chunk_index / section_path / content
    dense_vector / sparse_vector

DELETE /knowledge/documents/{document_id}
  ↓ 单文档 Milvus 删除 → 单文档 Neo4j 删除
DELETE /knowledge/sources/{source_type}?source_id=...
  ↓ 按来源找文档 → Milvus 删除 → 逐个 document_id 删除图
DELETE /knowledge/directories
  ↓ 按 source_path 前缀 → Milvus 删除 → 同步删除图

Neo4j 删除失败 → warning → 不阻断已成功的 Milvus 删除

同名不等于覆盖；三项来源身份完全一致，document_id 才一致

node_answer_output
  ↓
State.answer 已存在？
  ├── 是 → 保存 assistant → final → 结束
  └── 否 → chat_summary + 最近原始历史
             ↓
           reranked_docs 为空？
             ├── chitchat → CHAT_PROMPT → LLM
             ├── 无结果 → NO_RESULT_PROMPT → 兜底回答

前端任务链

查询：POST /query → task_id → EventSource(/stream/{task_id})
  ├── progress → 节点、耗时和状态
  ├── context_info → 召回上下文和来源
  ├── delta → 增量答案
  └── final → 最终答案、图片、完成状态

导入：POST /upload /upload_obsidian /import_local → task_id
  ↓
轮询 /status/{task_id}
  ↓
running_list / done_list / durations / error_msg
  ↓
completed / failed / cancelled

停止：POST /query/{task_id}/cancel → 设置取消状态
  ↓
后台查询节点检查取消信号 → 停止后续处理或结束流
